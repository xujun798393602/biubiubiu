## 1. 概述

本文档从 DFX（面向 X 的设计）7个维度出发，系统性地定义自动化测试平台的非功能性设计措施，确保系统在安全性、可靠性、可测试性、可调试性、可运维性、可扩展性、可复用性方面满足要求。

## 2. 安全性设计（Security）

### 2.1 认证安全

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 密码加密存储 | 使用 bcrypt 算法，cost factor=12 | 数据库中不存储明文密码 |
| JWT Token 认证 | HS256 签名，有效期24小时，支持黑名单 | Token 过期或在黑名单中时返回401 |
| 登录失败锁定 | 连续5次失败锁定1小时，存储于Redis | 第6次尝试返回423 ACCOUNT_LOCKED |
| Token 黑名单 | 退出时 Token 加入 Redis 黑名单，TTL=剩余有效期 | 退出后旧 Token 立即失效 |
| 验证码安全 | 6位数字，5分钟有效期，一次性使用 | 验证码过期或已使用返回错误 |

### 2.2 授权安全

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| RBAC 权限控制 | 3种角色（ADMIN/TESTER/OPS），通过 `require_roles()` 装饰器实现 | 无权限访问返回403 |
| 接口级权限校验 | 每个接口声明所需角色，中间件统一校验 | 未声明角色的接口拒绝访问 |
| 资源级权限 | 用户只能操作自己创建的资源（TESTER角色） | 越权操作返回403 |

### 2.3 输入安全

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 参数校验 | Pydantic Schema 校验所有请求参数 | 无效参数返回422 VALIDATION_ERROR |
| SQL 注入防护 | SQLAlchemy ORM 参数化查询 | 无原始 SQL 拼接 |
| XSS 防护 | 输出时 HTML 转义，Content-Type 设置正确 | 前端不执行注入脚本 |
| CORS 白名单 | Nginx 配置 CORS 允许域名列表 | 非白名单域名请求被拒绝 |
| 请求大小限制 | Nginx client_max_body_size=50MB | 超大请求返回413 |

### 2.4 传输安全

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| HTTPS 支持 | Nginx SSL 终端，TLS 1.2+ | HTTP 请求自动重定向到 HTTPS |
| 敏感数据脱敏 | 日志中不记录密码、Token 原文 | 日志中密码显示为 `***` |

### 2.5 审计安全

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 操作日志记录 | 所有写操作记录到 system_logs 表 | 每条日志包含操作人、操作类型、资源、IP、时间 |
| 登录日志 | 登录成功/失败均记录 | 包含账号、IP、时间、状态 |
| 日志不可篡改 | 日志表只允许 INSERT，不允许 UPDATE/DELETE | 应用层无修改日志的接口 |

## 3. 可靠性设计（Reliability）

### 3.1 错误处理

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 统一异常处理 | Flask 全局异常处理器，捕获所有未处理异常 | 所有异常返回统一格式错误响应 |
| 业务异常分类 | 定义16个业务错误码，每种对应明确HTTP状态码 | 错误响应包含 code、message |
| 数据库异常处理 | 连接失败自动重试3次，间隔1s/2s/4s | 重试失败返回500 |
| Redis 异步降级 | Redis 不可用时 Token 校验降级为数据库查询 | 核心功能不因 Redis 故障中断 |

### 3.2 超时控制

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| API 超时 | Gunicorn worker 超时30秒 | 超时返回503 |
| 数据库查询超时 | SQLAlchemy pool_timeout=10s, pool_recycle=3600s | 连接池不泄漏 |
| 外部调用超时 | httpx/requests timeout=30s | 不无限等待 |
| 用例执行超时 | UI用例60s，接口用例30s（可配置） | 超时标记为ERROR |

### 3.3 节点故障处理

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 心跳检测 | 节点每30秒上报心跳 | 超过90秒未收到心跳标记OFFLINE |
| 离线节点任务重分配 | 调度器检测到节点离线后，将其RUNNING任务重新入队 | 任务不因单节点故障丢失 |
| 节点资源监控 | 心跳上报 CPU/内存/磁盘使用率 | 负载过高时不再分配新任务 |

### 3.4 任务执行可靠性

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 任务状态机 | 严格的状态转换：PENDING→RUNNING→SUCCESS/FAILED/CANCELLED | 非法状态转换被拒绝 |
| 执行结果持久化 | 每个用例执行完立即写入 test_results | 进程崩溃不丢失已完成的结果 |
| 幂等操作 | 任务启动/取消操作幂等 | 重复操作返回成功而非报错 |

### 3.5 数据可靠性

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 数据库备份 | 每日全量备份 + WAL 连续归档 | RPO ≤ 5分钟 |
| 软删除 | users/test_cases/tasks 使用 deleted_at | 数据可恢复 |
| 事务边界 | 关联操作在同一事务中 | 部分失败时全部回滚 |

## 4. 可测试性设计（Testability）

### 4.1 单元测试

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 分层架构 | Controller → Service → Repository 三层分离 | 每层可独立测试 |
| 依赖注入 | Service 层通过构造函数注入 Repository | 可 Mock 依赖 |
| 测试框架 | pytest + pytest-cov | 核心模块覆盖率 ≥ 80% |
| 测试数据工厂 | 使用 factory_boy 生成测试数据 | 测试不依赖外部数据 |

### 4.2 集成测试

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| API 测试 | 使用 Flask test client 测试所有接口 | 接口正常和异常场景全覆盖 |
| 数据库测试 | 使用测试数据库，每个测试后回滚 | 测试间不互相影响 |
| Redis 测试 | 使用独立的测试 Redis 实例 | 缓存逻辑可验证 |

### 4.3 端到端测试

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| E2E 测试 | 使用 Playwright 测试前端关键流程 | 登录、创建用例、执行任务等核心流程通过 |
| 测试环境 | Docker Compose 一键启动完整环境 | 测试环境与生产环境一致 |

### 4.4 测试辅助

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| Mock 服务 | 节点客户端可 Mock，不依赖真实节点 | 任务调度逻辑可独立测试 |
| 测试配置 | 独立的测试配置文件 | 测试不修改生产配置 |
| 断言工具 | 提供 API 响应断言辅助函数 | 测试代码简洁可读 |

## 5. 可调试性设计（Debuggability）

### 5.1 日志设计

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 结构化日志 | 使用 Python logging + JSON 格式 | 日志可被 ELK 等工具解析 |
| 日志级别 | DEBUG/INFO/WARNING/ERROR，可配置 | 配置变更后立即生效 |
| 按模块分文件 | `data/YYYYMMDD/module/xxx.log` | 各模块日志独立 |
| 日志轮转 | 单文件最大10MB，超过自动轮转 | 磁盘不被日志撑满 |
| 请求ID追踪 | 每个请求生成唯一 request_id，贯穿整个调用链 | 可通过 request_id 追踪完整请求 |

### 5.2 日志内容

| 场景 | 日志级别 | 必须包含的字段 |
|------|---------|--------------|
| API 请求 | INFO | request_id, method, path, status_code, duration_ms, user_id |
| 业务错误 | WARNING | request_id, error_code, message, context |
| 系统异常 | ERROR | request_id, exception_type, traceback, context |
| 数据库慢查询 | WARNING | query, duration_ms, params |
| 任务执行 | INFO | task_id, case_id, status, duration_ms |

### 5.3 调试辅助

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 健康检查接口 | `/health` 和 `/ready`，无需认证 | 可快速判断服务状态 |
| 调试模式 | Flask debug=True 时返回详细错误堆栈 | 仅在开发环境启用 |
| 配置热加载 | 系统配置修改后无需重启 | 日志级别等配置实时生效 |

| 措施 | 具体实现 | 验收标准 |

| 关键指标 | 任务成功率、API 响应时间、节点在线数 | 指标可采集 |
| 告警规则 | 节点离线、任务失败率>10%、API 响应>3s | 触发平台内通知 |

### 6.3 日志管理

| 日志总开关 | 可全局关闭日志记录 | 关闭后不产生日志文件 |

### 6.4 数据运维

| 措施 | 具体实现 | 验收标准 |
|------|---------|---------|
| 数据备份 | 每日全量备份，支持手动触发 | 备份文件可用于恢复 |
| 数据清理 | 定时清理过期日志、过期分享链接 | 磁盘空间可控 |
| 数据迁移工具 | 提供数据导出/导入脚本 | 支持跨环境迁移 |

## 9. FMEA 失效模式分析

### 9.1 关键业务流程失效分析

| 失效模式 | 失效影响 | 失效原因 | 严重度(S) | 发生度(O) | 探测度(D) | AP | 改进措施 |
|---------|---------|---------|----------|----------|----------|-----|---------|
| 用户登录失败 | 用户无法使用平台 | 密码错误/账号锁定/服务不可用 | 高 | 中 | 低 | 高 | 登录失败提示明确，锁定自动恢复，服务健康检查 |
| 任务创建失败 | 测试工作受阻 | 用例不存在/参数错误 | 中 | 低 | 低 | 中 | 参数校验前置，错误信息明确 |
| 任务执行超时 | 测试结果不完整 | 节点故障/用例脚本问题 | 高 | 中 | 中 | 高 | 超时自动标记ERROR，节点心跳检测，失败用例记录详情 |
| 节点离线 | 任务无法执行 | 网络故障/进程崩溃 | 高 | 中 | 低 | 高 | 心跳检测90秒超时，离线任务重分配 |
| 数据库连接失败 | 所有功能不可用 | 连接池耗尽/数据库宕机 | 高 | 低 | 低 | 高 | 连接池监控，自动重试，降级方案 |
| Redis 不可用 | Token 校验失败/缓存失效 | Redis 宕机 | 高 | 低 | 低 | 高 | 降级为数据库查询，Redis 哨兵/集群 |
| 磁盘空间不足 | 日志/录像/截图无法存储 | 大量测试结果积累 | 高 | 中 | 中 | 高 | 日志轮转，定期清理，磁盘监控告警 |

### 9.2 资源使用上限控制

| 资源 | 上限 | 控制方式 | 超限处理 |
|------|------|---------|---------|
| 数据库连接数 | 200 | 连接池配置 | 请求排队等待 |
| 单任务用例数 | 100 | 参数校验 | 返回422错误 |
| 节点并发数 | 可配置(默认5) | 调度器控制 | 任务等待 |
| 上传文件大小 | 50MB | Nginx 限制 | 返回413错误 |
| 日志文件大小 | 10MB/文件 | 日志轮转 | 自动创建新文件 |
| 日志保留天数 | 90天(可配置) | 定时清理任务 | 自动删除过期日志 |
| Token 有效期 | 24小时 | JWT 过期时间 | 需重新登录或刷新 |
