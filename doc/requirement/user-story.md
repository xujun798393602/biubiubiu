# 自动化测试平台 — 用户需求文档

> 版本：1.0 | 日期：2026-05-12 | 状态：阶段一完成，待用户确认

## 技术栈确认

| 层次 | 技术选型 |
|------|---------|
| 前端 | Vue 3 + Element Plus |
| 反向代理 | Nginx |
| 后端 | Flask + Python |

## Epic 1：身份认证与权限管理

> 核心目标：保障平台安全性，实现身份认证和权限管控，防止未授权访问。

### Feature 1.1 账号登录

#### STORY-1.1.1 账号密码登录
**作为** 测试人员/运维人员  
**我希望** 通过账号密码登录平台  
**以便** 安全地访问平台功能

**验收条件：**
- **Given** 用户已在平台注册账号  
  **When** 输入正确的用户名和密码，点击登录  
  **Then** 系统验证通过，跳转到仪表盘页面，返回 JWT Token

- **Given** 用户输入错误的密码  
  **When** 点击登录  
  **Then** 系统提示"用户名或密码错误"，不泄露具体哪个字段错误

- **Given** 用户密码不符合复杂度要求  
  **When** 设置/修改密码  
  **Then** 系统要求密码长度≥8位，包含字母+数字+特殊符号

#### STORY-1.1.2 登录安全防护
**作为** 系统管理员  
**我希望** 平台具备登录安全防护机制  
**以便** 防止暴力破解攻击

**验收条件：**
- **Given** 用户连续5次输入错误密码  
  **When** 第6次尝试登录  
  **Then** 系统锁定该账号1小时，提示"账号已锁定，请X分钟后重试"

- **Given** 用户成功登录  
  **When** 系统记录登录日志  
  **Then** 日志包含：登录账号、登录时间、登录IP、登录状态（成功/失败）

### Feature 1.2 权限分级

#### STORY-1.2.1 管理员权限
**作为** 管理员  
**我希望** 拥有平台全部操作权限  
**以便** 管理平台所有功能和用户

**验收条件：**
- **Given** 用户角色为管理员  
  **When** 访问任意功能模块  
  **Then** 可执行所有操作：用户管理、用例管理、任务管理、机器管理、系统配置

#### STORY-1.2.2 测试人员权限
**作为** 测试人员  
**我希望** 拥有测试相关操作权限  
**以便** 执行日常测试工作

**验收条件：**
- **Given** 用户角色为测试人员  
  **When** 访问用例管理、任务管理、结果展示  
  **Then** 可执行：用例创建/编辑/查询、任务创建/查看、结果查看/导出

- **Given** 用户角色为测试人员  
  **When** 访问用户管理、系统配置  
  **Then** 系统拒绝访问，提示"权限不足"

#### STORY-1.2.3 运维人员权限
**作为** 运维人员  
**我希望** 拥有机器管理和系统监控权限  
**以便** 管理测试节点和监控系统状态

**验收条件：**
- **Given** 用户角色为运维人员  
  **When** 访问测试机器管理、系统监控、日志查看  
  **Then** 可执行：机器管理、状态监控、日志查看

- **Given** 用户角色为运维人员  
  **When** 访问用例管理、任务管理  
  **Then** 系统拒绝访问，提示"权限不足"

### Feature 1.3 密码找回

#### STORY-1.3.1 邮箱找回密码
**作为** 忘记密码的用户  
**我希望** 通过绑定邮箱找回密码  
**以便** 重新获得平台访问权限

**验收条件：**
- **Given** 用户已绑定邮箱  
  **When** 点击"忘记密码"，输入账号  
  **Then** 系统发送验证码到绑定邮箱，5分钟内有效

- **Given** 用户输入正确的验证码  
  **When** 设置新密码  
  **Then** 密码重置成功，旧密码失效，可立即用新密码登录

### Feature 1.4 退出登录

#### STORY-1.4.1 手动退出
**作为** 已登录用户  
**我希望** 能手动退出登录  
**以便** 保护账号安全

**验收条件：**
- **Given** 用户已登录  
  **When** 点击退出登录  
  **Then** 清除本地 Token，跳转到登录页，Token 加入黑名单失效

## Epic 2：用例管理

> 核心目标：实现测试用例的规范化管理，支持 UI/接口/性能三类用例的创建、编辑、查询、复用。

### Feature 2.1 用例分类

#### STORY-2.1.1 按测试类型分类
**作为** 测试人员  
**我希望** 用例按测试类型（UI/接口/性能）分类管理  
**以便** 快速定位和管理不同类型的用例

**验收条件：**
- **Given** 平台已初始化  
  **When** 用户进入用例管理页面  
  **Then** 看到 UI 测试、接口测试、性能压测三大分类，每类下可创建子分类

- **Given** 用户需要自定义分类  
  **When** 创建自定义分类（如按业务模块）  
  **Then** 分类创建成功，可将用例归入自定义分类

### Feature 2.2 用例创建与编辑

#### STORY-2.2.1 UI 测试用例 — 录制模式
**作为** 测试人员  
**我希望** 通过录制浏览器操作自动生成 UI 测试用例  
**以便** 无需手动编写脚本，降低用例创建门槛

**验收条件：**
- **Given** 用户选择"录制模式"创建 UI 用例  
  **When** 在录制器中操作浏览器（点击、输入、跳转）  
  **Then** 系统自动录制操作步骤，生成 Playwright 脚本

- **Given** 录制完成  
  **When** 用户保存用例  
  **Then** 脚本保存成功，可回放验证，支持编辑修改

#### STORY-2.2.2 UI 测试用例 — 手动编写模式
**作为** 高级测试人员  
**我希望** 手动编写 Playwright 脚本  
**以便** 实现复杂的测试逻辑和自定义断言

**验收条件：**
- **Given** 用户选择"手动编写"模式  
  **When** 在代码编辑器中编写 Playwright 脚本  
  **Then** 编辑器支持语法高亮、语法校验，保存时检查脚本有效性

- **Given** 用户编写了包含断言的脚本  
  **When** 保存用例  
  **Then** 系统解析断言规则，记录预期结果

#### STORY-2.2.3 UI 测试用例 — 平台管理脚本
**作为** 测试人员  
**我希望** 在平台上管理（查看/编辑/版本对比/回滚）UI 测试脚本  
**以便** 实现脚本的版本控制和团队协作

**验收条件：**
- **Given** 用例已创建  
  **When** 用户查看用例详情  
  **Then** 展示脚本内容、版本历史、修改记录

- **Given** 用例有多个版本  
  **When** 用户选择回滚到历史版本  
  **Then** 脚本恢复到指定版本，生成新版本记录

#### STORY-2.2.4 接口测试用例
**作为** 测试人员  
**我希望** 创建接口测试用例  
**以便** 验证 RESTful API 的请求和响应

**验收条件：**
- **Given** 用户创建接口测试用例  
  **When** 填写接口地址、请求方法（GET/POST/PUT/DELETE）、请求头、请求参数  
  **Then** 用例保存成功，支持表单和 JSON 两种参数格式

- **Given** 用户配置断言规则  
  **When** 设置响应状态码、响应内容、响应时间的断言  
  **Then** 断言规则保存成功，执行时自动验证

- **Given** 用户需要配置接口依赖  
  **When** 设置前置接口的返回值作为当前接口的参数  
  **Then** 依赖关系保存成功，执行时按顺序自动传递参数

#### STORY-2.2.5 性能压测用例
**作为** 测试人员  
**我希望** 创建基于 Locust 的性能压测用例  
**以便** 模拟高并发场景，验证系统性能

**验收条件：**
- **Given** 用户创建性能压测用例  
  **When** 设置并发用户数、用户增长率、压测持续时间、目标接口  
  **Then** 用例保存成功，生成 Locust 压测脚本

- **Given** 用户需要自定义压测逻辑  
  **When** 编写 Locust 脚本或导入已有脚本  
  **Then** 脚本保存成功，支持语法校验

#### STORY-2.2.6 用例属性管理
**作为** 测试人员  
**我希望** 每个用例包含完整的属性信息  
**以便** 便于用例的管理和检索

**验收条件：**
- **Given** 用户创建/编辑用例  
  **When** 填写用例信息  
  **Then** 必填属性：用例名称、测试类型、优先级（P0/P1/P2/P3）；可选属性：所属模块、标签、前置条件、描述

### Feature 2.3 用例查询与筛选

#### STORY-2.3.1 多条件组合查询
**作为** 测试人员  
**我希望** 通过多条件组合查询用例  
**以便** 快速找到目标用例

**验收条件：**
- **Given** 用例列表页面  
  **When** 用户按名称、类型、状态、优先级、创建人、创建时间组合筛选  
  **Then** 返回匹配的用例列表，支持模糊搜索

- **Given** 查询结果较多  
  **When** 用户翻页  
  **Then** 分页展示，每页可选 10/20/50 条

### Feature 2.4 用例版本管理

#### STORY-2.4.1 版本记录与回滚
**作为** 测试人员  
**我希望** 用例修改时自动记录版本  
**以便** 追溯修改历史，必要时回滚

**验收条件：**
- **Given** 用户修改并保存用例  
  **When** 保存成功  
  **Then** 自动递增版本号，记录修改时间、修改人、变更内容

- **Given** 用例有多个历史版本  
  **When** 用户选择回滚到指定版本  
  **Then** 用例内容恢复到该版本，当前版本号递增

### Feature 2.5 用例导入导出

#### STORY-2.5.1 批量导入导出
**作为** 测试人员  
**我希望** 批量导入导出用例  
**以便** 跨项目复用用例，便于归档

**验收条件：**
- **Given** 用户选择导出用例  
  **When** 选择导出格式（Excel/JSON）和用例范围  
  **Then** 生成下载文件，包含用例完整信息

- **Given** 用户有导入文件  
  **When** 上传 Excel/JSON 文件  
  **Then** 系统解析文件，预览导入内容，确认后批量创建用例

## Epic 3：任务管理

> 核心目标：支持选中多个用例批量创建测试任务，实现任务的调度、执行、监控。

### Feature 3.1 任务创建

#### STORY-3.1.1 批量选用例创建任务
**作为** 测试人员  
**我希望** 从用例列表中勾选多个用例，批量创建测试任务  
**以便** 一次性执行多组测试用例

**验收条件：**
- **Given** 用户在用例列表中勾选了多个用例（可跨类型）  
  **When** 点击"创建任务"  
  **Then** 弹出任务配置表单，已选用例显示在关联列表中

- **Given** 用户填写任务名称、选择执行方式（立即/定时）、选择执行节点  
  **When** 提交创建  
  **Then** 任务创建成功，状态为"待执行"或"已调度"

#### STORY-3.1.2 定时任务
**作为** 测试人员  
**我希望** 设置定时执行的测试任务  
**以便** 实现自动化回归测试

**验收条件：**
- **Given** 用户选择"定时执行"  
  **When** 设置执行时间（如每天凌晨2点、每周五下午）  
  **Then** 任务创建成功，状态为"已调度"，显示下次执行时间

- **Given** 定时任务已创建  
  **When** 用户暂停/启用/删除定时任务  
  **Then** 操作立即生效，暂停后不再自动执行

### Feature 3.2 任务执行

#### STORY-3.2.1 任务调度与并发执行
**作为** 系统  
**我希望** 根据任务优先级和节点负载自动调度任务  
**以便** 充分利用测试资源，避免节点过载

**验收条件：**
- **Given** 有多个待执行任务  
  **When** 系统调度任务  
  **Then** 按优先级（高>中>低）顺序调度，优先分配到负载最低的节点

- **Given** 单个任务包含多个用例  
  **When** 任务开始执行  
  **Then** 支持用例并发执行，并发数根据节点配置和测试类型自动调整

#### STORY-3.2.2 任务操作
**作为** 测试人员  
**我希望** 在任务执行过程中进行控制操作  
**以便** 灵活管理测试流程

**验收条件：**
- **Given** 任务状态为"待执行"  
  **When** 用户点击"启动"  
  **Then** 任务立即开始执行，状态变为"执行中"

- **Given** 任务状态为"执行中"  
  **When** 用户点击"终止"  
  **Then** 任务停止执行，状态变为"已终止"，已执行的用例结果保留

#### STORY-3.2.3 执行日志
**作为** 测试人员  
**我希望** 实时查看任务执行日志  
**以便** 监控执行过程，排查问题

**验收条件：**
- **Given** 任务正在执行  
  **When** 用户查看执行日志  
  **Then** 实时展示日志：执行时间、用例名称、执行状态、错误信息

- **Given** 任务执行完成  
  **When** 用户导出日志  
  **Then** 生成日志文件下载

### Feature 3.3 任务管理

#### STORY-3.3.1 任务状态与查询
**作为** 测试人员  
**我希望** 查看任务列表和状态  
**以便** 掌握测试任务整体情况

**验收条件：**
- **Given** 任务列表页面  
  **When** 用户查看任务列表  
  **Then** 展示任务名称、状态（待执行/执行中/成功/失败/已终止）、优先级、用例数、创建人、创建时间

- **Given** 用户需要筛选任务  
  **When** 按名称、状态、优先级、创建人筛选  
  **Then** 返回匹配的任务列表

  **When** 用户点击"导出报告"  
  **Then** 支持导出为 Excel/PDF/HTML 格式，包含完整的测试结果数据

#### STORY-4.3.2 生成分享链接
**作为** 测试人员  
**我希望** 生成结果分享链接  
**以便** 无需登录即可查看测试结果

**验收条件：**
- **Given** 任务执行完成  
  **When** 用户点击"分享"，设置有效期和密码（可选）  
  **Then** 生成分享链接，可通过链接查看结果，过期后失效

## Epic 5：测试节点管理

> 核心目标：实现测试机器的统一管理，支持状态监控、资源分配、横向扩充。

### Feature 5.1 节点注册

#### STORY-5.1.1 节点注册与信息管理
**作为** 运维人员  
**我希望** 将测试机器注册到平台  
**以便** 纳入统一管理

**验收条件：**
- **Given** 运维人员安装了节点客户端/代理  
  **When** 客户端启动并连接平台  
  **Then** 节点自动注册，显示在节点列表中，记录：名称、IP、系统、CPU、内存、磁盘

- **Given** 管理员手动录入节点  
  **When** 填写节点信息（名称、IP、端口）  
  **Then** 节点创建成功，状态为"离线"，等待客户端连接

### Feature 5.2 节点监控

#### STORY-5.2.1 实时状态监控
**作为** 运维人员  
**我希望** 实时查看节点状态  
**以便** 及时发现和处理异常

**验收条件：**
- **Given** 节点已注册  
  **When** 用户查看节点列表  
  **Then** 展示每个节点的状态（在线/离线/忙碌）、CPU/内存/磁盘使用率、当前任务数

- **Given** 节点离线或负载过高  
  **When** 系统检测到异常  
  **Then** 通过平台消息通知运维人员

#### STORY-5.2.2 节点心跳
**作为** 系统  
**我希望** 定期检测节点是否在线  
**以便** 及时发现离线节点

**验收条件：**
- **Given** 节点已上线  
  **When** 超过90秒未收到心跳  
  **Then** 系统自动将节点标记为"离线"，不再分配新任务

### Feature 5.3 节点分组

#### STORY-5.3.1 节点分组管理
**作为** 运维人员  
**我希望** 将节点按用途分组  
**以便** 统一管理和任务分配

**验收条件：**
- **Given** 有多个已注册节点  
  **When** 创建节点组（如"UI测试组"、"性能测试组"），将节点加入组  
  **Then** 分组创建成功，节点归属关系建立

- **Given** 创建测试任务时  
  **When** 用户选择指定节点组执行  
  **Then** 任务分配到该组内的可用节点

### Feature 5.4 节点操作

#### STORY-5.4.1 节点禁用与启用
**作为** 运维人员  
**我希望** 禁用故障节点  
**以便** 防止任务分配到不可用节点

**验收条件：**
- **Given** 节点出现故障  
  **When** 运维人员禁用该节点  
  **Then** 节点状态变为"已禁用"，不再分配新任务，正在执行的任务继续完成

- **Given** 节点已修复  
  **When** 运维人员启用该节点  
  **Then** 节点恢复"在线"状态，可正常接收任务

## Epic 6：系统管理

> 核心目标：提供系统日志、消息通知、配置管理等辅助功能。

### Feature 6.1 系统日志

#### STORY-6.1.1 操作日志记录
**作为** 管理员  
**我希望** 查看平台所有操作日志  
**以便** 审计和问题排查

**验收条件：**
- **Given** 用户在平台上执行操作（登录、创建用例、执行任务等）  
  **When** 操作完成  
  **Then** 系统自动记录操作日志：操作人、操作类型、资源类型、操作描述、时间、IP

- **Given** 管理员查看日志列表  
  **When** 按操作类型、时间、操作人筛选  
  **Then** 返回匹配的日志记录，支持导出

### Feature 6.2 消息通知

#### STORY-6.2.1 平台内通知
**作为** 用户  
**我希望** 收到平台内的消息通知  
**以便** 及时了解任务结果和系统异常

**验收条件：**
- **Given** 任务执行完成/失败  
  **When** 系统生成通知  
  **Then** 任务创建人收到通知：任务名称、执行结果、时间

- **Given** 节点离线/负载过高  
  **When** 系统检测到异常  
  **Then** 运维人员和管理员收到通知

### Feature 6.3 系统配置

#### STORY-6.3.1 平台参数配置
**作为** 管理员  
**我希望** 配置平台运行参数  
**以便** 调整平台行为

**验收条件：**
- **Given** 管理员进入系统配置页面  
  **When** 修改配置项（登录失败限制、通知规则、节点默认配置等）  
  **Then** 配置保存成功，部分配置需重启生效，页面提示说明
